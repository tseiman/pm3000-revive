# Stage 5 Web UI

This directory contains the dependency-free PM3000 read-only Web UI.

## Security properties

- The browser receives only the strict REST v1 projections.
- The bearer token remains in JavaScript memory and is cleared on disconnect, authentication loss, or page close. It is not written to browser storage, URLs, or logs.
- API values are rendered with DOM `textContent`; no API value reaches an HTML parsing or dynamic-code sink.
- The outlet view has no switching controls. Stage 5 does not call the reserved `/actions` route.
- Token management uses only the fixed `admin` routes from `api/openapi-v1.json`. Existing token plaintext and digests are never displayed.
- All assets are local. There is no framework, CDN, package manager, font download, or runtime third-party dependency.

Production assets are:

```text
index.html
styles.css
app.js
```

## Local fake-adapter preview

The preview server binds to loopback and uses synthetic data only. It never opens the production Avtrans socket or contacts a PM3000.

```bash
python3 modern-WebUI/tools/fake_ui_server.py --bind 127.0.0.1 --port 8765
```

Open `http://127.0.0.1:8765/` and enter:

```text
synthetic-preview-token
```

`/preview` is a local test-server route that injects the same synthetic token through a separate `preview-app.js` response. That route and asset are generated by the fake server and are not part of the production Web root.

## Verification

Focused static and contract checks:

```bash
python3 -m unittest modern-WebUI/tests/test_web_ui.py
node --check modern-WebUI/web/app.js
```

The readiness-aware browser check requires Firefox plus a running WebDriver on `127.0.0.1:4444`. It waits for eight outlet cards, proves that dialog cancellation does not mutate state, rejects duplicate submission, exercises restricted and unrestricted token creation, checks native-dialog and disconnect secret cleanup plus `204` disable/enable/revoke handling, and then captures desktop and narrow screenshots. Firefox headless currently enforces a 450-pixel minimum outer window (438 CSS pixels); the check records that real narrow layout and asserts zero horizontal overflow rather than claiming unsupported 390-pixel emulation:

```bash
python3 modern-WebUI/tools/browser_check.py
```

Screenshots are test artifacts, not release payloads. A screenshot proves rendered layout only; the automated readiness assertions and API request log provide the behavioral evidence.
